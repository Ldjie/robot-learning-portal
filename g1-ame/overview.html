1. 项目阅读地图

建议从项目自身的 README、训练命令与配置文件出发，沿着环境、采样、网络、更新和部署追踪，不根据目录名猜测实现。

层次需要定位的对象要记录的证据
运行入口命令行脚本、训练 runner、配置加载启动命令、配置覆盖规则、输出目录
环境机器人模型、观测、动作、奖励、reset / termination维度、单位、调用时序、终止逻辑
算法rollout storage、PPO 更新、优化器loss 公式、超参数、log probability 计算
网络Actor、Critic、encoder、可能存在的 Attention类名、前向传播、实际张量形状
评估与部署checkpoint、推理入口、控制接口策略版本、控制频率、归一化和动作映射

2. 推荐阅读顺序

  1. 先读 README 与启动命令，记录训练入口和依赖版本。
  2. 从配置读取 observation/action 维度和训练参数。
  3. 追踪环境如何生成观测、奖励、终止标记和重置状态。
  4. 追踪 rollout 如何采样、计算优势并存储训练数据。
  5. 追踪 policy forward、动作分布、动作变换和 loss。
  6. 最后再对照部署端，核实是否使用相同预处理与动作语义。

3. 记录事实时使用证据链

每条项目结论尽量包含：文件路径 → 类 / 函数 → 配置或代码行 → 运行日志 / shape → 结论。标注源码 commit 或版本，避免仓库变化后旧笔记失去上下文。

建议在笔记中明确区分：

  • 已核实事实：能由源码、配置或日志直接支持。
  • 实验观察：特定版本、配置、种子和测试条件下测得。
  • 解释假设：对原因的推测，需要后续实验区分。
