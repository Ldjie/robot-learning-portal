1. 前向传播数据流

观测 obs → 归一化 / 分组 → 特征编码器 →（若存在）Attention → Policy trunk → 动作分布 / 动作输出

这是用于阅读代码的通用追踪框架，不代表 AME 当前使用了所有这些模块。请从实际的 forward 函数中确认每个节点。

2. 张量形状记录表

节点形状（实测填写）要确认的语义
原始 obs[B, D_obs] 或项目实际结构字段顺序、单位、归一化、历史维
编码前待核实是否 split、reshape、拼接或加入噪声
空间 / 序列特征待核实各维对应通道、时间、空间还是 token
Attention 输入待核实batch_first、序列长度、embedding dim、head 数
策略输出待核实动作维度、分布参数、缩放、裁剪

例如，[B, 64, 11, 17] 若后两维是空间网格，将这两维展平通常得到 [B, 64, 187]；但必须先确认 64 的语义。展平并不自动保留显式二维邻接关系，后续模块是否有位置编码也需核实。

3. 如何逐步追踪 shape

  1. 在输入入口打印 shape、dtype、device、最小值和最大值。
  2. 每遇到 split、reshape、permute / transpose、flatten、cat 都记录结果。
  3. 在注意力层前确认实际参数：输入布局、序列长度、embed_dim、head 数和 mask。
  4. 在动作输出处核实维度、均值/标准差或确定性动作路径。
  5. 对训练和部署分别运行一条样本，比较预处理结果与最终输出。

4. 常见错误

  • 布局错位：把 [B,L,D] 当成 [L,B,D]，但没有同步设置 batch_first。
  • Mask 误用：没有核对 API 中 True/False 的含义、形状和广播规则。
  • 时间错位：训练和部署的历史顺序、当前帧、缓存更新策略不同。
  • 归一化不一致：部署端没有加载训练期的统计量或处理顺序不同。
  • 动作映射差异：输出维度对了，但关节顺序、缩放或 PD 目标不一致。
