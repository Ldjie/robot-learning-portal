学习路线与先修知识

建议按顺序学习，不需要一开始就掌握所有 Transformer 变体。你只需要具备矩阵乘法、向量、概率分布和基本 PyTorch 张量操作的概念。

阶段 A：建立直觉

理解为什么需要动态聚合、Q/K/V 的角色、Softmax 权重。

阶段 B：理解架构

学习 Mask、多头注意力、残差、归一化与位置编码。

阶段 C：动手实现

运行 PyTorch 代码，检查形状、Mask 和数值行为。

阶段 D：机器人实验

提出假设，建立公平基线，比较任务效果与推理成本。

关键原则：注意力是一种信息交互/聚合机制，不是自动提高性能的开关。是否有帮助，取决于数据结构、任务需求、训练设置与部署预算。

01 · 为什么需要注意力？

假设机器人策略接收最近 20 帧观测，每帧包括关节位置、关节速度、基座姿态和目标指令。把全部观测拼接后输入 MLP 当然可行，但 MLP 并没有显式的“从一个时刻读取另一个时刻信息”的结构先验；它需要通过参数学习这种关系。

注意力允许每个位置根据当前输入，动态地决定从哪些其他位置聚合信息。不同输入会产生不同的注意力权重，因此它是一种内容相关的信息路由方式。

直觉示例：脚端刚刚接触障碍物时，当前决策可能需要更多参考最近几帧的足端运动；在稳定周期运动时，较长时间范围的节律信息可能有用。注意力提供学习这些关系的能力，但并不保证模型一定学出这种行为。

注意力与普通加权平均的差异

固定加权平均使用预先设定或固定学习的权重；自注意力的权重会由输入内容计算得到。它可以针对不同样本、不同 Query 位置生成不同的聚合权重。

02 · Query、Key、Value 分别是什么？

可以把输入序列中的每个位置想象成一张信息卡片：

Query（查询，Q）

当前这个位置正在寻找什么信息。它决定用什么特征去匹配其他位置。

Key（键，K）

每个位置提供用于匹配的特征。Query 与 Key 的相似程度决定分数。

Value（值，V）

匹配后真正被取出并聚合的信息内容。

可学习投影

Q、K、V 通常由同一输入 X 乘以不同的可学习矩阵得到，而不是人工指定语义。

X ∈ ℝⁿˣᵈ
Q = XWQ，K = XWK，V = XWV
n：序列长度；d：输入特征维度
WQ、WK、WV：训练得到的参数矩阵

为什么要用三组不同的投影？因为“用于比较的特征”和“要传递的内容”不必相同。模型可以学习用一套表示判断相关性，再用另一套表示传递信息。

注意：Q/K/V 的比喻只是帮助理解，不表示 Query 必须是自然语言问题，Key 必须是标签，Value 必须是原始输入。在神经网络中，它们是可学习的向量表示。

03 · 数学计算全过程

缩放点积注意力的标准形式是：

Attention(Q,K,V) = softmax(QKᵀ / √dk) V

步骤 1：计算匹配分数

S = QKᵀ / √dk

若 Q 有 n 个 Query，K 有 n 个 Key，QKᵀ 就是 n×n 矩阵。S 的第 i 行第 j 列表示第 i 个 Query 与第 j 个 Key 的匹配分数。

步骤 2：对每行做 Softmax

Aij = exp(Sij) / Σj exp(Sij)

Softmax 通常沿 Key/来源位置这个维度计算。每一行的权重非负，且在没有特殊 Mask 数值问题时，行和为 1。

步骤 3：加权聚合 Value

O = AV
oi = Σj Aij vj

每个输出向量是多个 Value 的加权和。权重越大，对输出的直接线性贡献通常越大，但不能仅凭权重就断言因果重要性。

手算小例子

假设一个 Query 对三个 Key 的分数为 [2, 1, 0]。Softmax 权重大约为 [0.665, 0.245, 0.090]，因此：

o = 0.665 v₁ + 0.245 v₂ + 0.090 v₃

第一个 Value 的权重最大，但其他两个仍然参与输出。若 Value 是多维向量，上式会对每个维度分别执行相同的加权求和。

自检：QKᵀ 产生的是“位置对位置”的分数矩阵；Softmax 把分数变成权重；乘 V 才把信息聚合成输出。注意力权重本身不是最终输出。

04 · 为什么要除以 √dk？

点积是多个维度乘积后求和。如果 Q、K 的各维分量尺度相近且近似独立，点积的方差通常会随维度 dk 增长。维度越大，分数可能越大，Softmax 就容易变得非常尖锐。

当某个权重接近 1、其余接近 0 时，Softmax 在饱和区的梯度可能很小，训练可能更难优化。除以 √dk 是一种控制分数尺度的方式。

未缩放分数：QKᵀ
缩放分数：QKᵀ / √dk

缩放通常不会改变同一行分数的排序，但会改变 Softmax 的分布尖锐程度。它不是为了让权重必然均匀，也不能保证训练绝对稳定。

05 · Mask：哪些位置可以被读取？

Padding Mask

不同样本序列长度不同时，批处理需要补齐。Mask 用于避免把补齐位置当成真实 Key/Value。

Causal Mask

自回归预测时，位置 t 不能读取未来的 t+1、t+2 等位置。

结构约束 Mask

某些模型会限制特定 token 之间的交互；需要有明确的建模理由。

机器人历史窗口

若所有输入都来自决策时刻之前，编码整个已知历史窗口通常不一定需要因果 Mask。

Mask 通常在 Softmax 前将不允许的位置分数设为很大的负数，使对应权重接近 0。实际 API 中，布尔 Mask 的 True/False 含义可能因参数类型不同而不同，必须查对应框架文档。

最重要的不是机械地加 Mask，而是明确数据的时间语义。把未来状态误放进输入会造成信息泄露；单纯使用某一种 Mask 并不能自动修复错误的数据构造。

06 · 多头注意力（Multi-Head Attention）

单头注意力只在一组投影空间中计算交互。多头注意力使用多套独立投影，让不同头在不同表示子空间中学习关系。

headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV)
MultiHead(Q,K,V) = Concat(head₁,…,headₕ) WO

各头输出通常先拼接，再通过输出投影 WO 映射到模型维度。某些头可能学习短期动态，某些头可能学习跨身体部位关系，但这是训练中可能形成的现象，不是架构保证。

维度示例

配置模型维度头数每头维度（常见设置）
A128432
B128816
C256832

常见设计满足 h × dhead = dmodel。增加头数不一定提升效果；在固定模型维度下，头数增加会使每头维度减小，也会带来实现和计算上的权衡。

07 · Self-Attention、Cross-Attention 与 MLP

Self-Attention

Q、K、V 来自同一组输入。适合让历史帧或身体部位 Token 彼此交换信息。

Cross-Attention

Q 来自一组输入，K/V 来自另一组输入。例如状态表示查询参考动作或地形特征。

MLP / FFN

通常在每个 Token 的特征维上做非线性变换，不直接执行 Token 与 Token 之间的交互。

残差与归一化

残差帮助信息和梯度跨层传播；LayerNorm 调整特征分布。具体顺序依架构而定。

Attention 和 MLP 不是互相替代的关系。Transformer 通常把 Token 间的信息交互与逐 Token 的非线性加工结合起来。

08 · Transformer Block 的组成

输入 X
↓
多头注意力（Token 间交互）
↓
残差连接 + LayerNorm（顺序依架构）
↓
前馈网络 FFN：Linear → 激活函数 → Linear
↓
残差连接 + LayerNorm
↓
输出

完整 Transformer 还可能包含位置编码、Dropout、门控结构或不同的归一化顺序。Pre-LN 和 Post-LN 的排列不同，阅读实际代码时应以实现为准。

为什么还需要 FFN？

注意力把不同 Token 的信息混合起来，而 FFN 对每个位置的表示做更丰富的非线性变换。只做注意力并不等于完成所有特征提取工作。

09 · 位置编码与时间信息

注意力运算本身并不会自动理解输入的先后顺序。如果没有位置信息，模型对 Token 排列的处理具有特定的置换性质，因此通常需要明确地提供位置或时间信息。

  • 绝对位置编码：给每个位置加入位置向量。
  • 相对位置方法：让模型利用 Token 之间的相对距离或位置关系。
  • 真实时间间隔：不规则采样、丢帧或不同采样周期下，可显式编码时间差。

机器人时序输入尤其要确认：帧顺序、采样频率、历史窗口长度、当前帧是否包含、观测是否延迟，以及训练和部署时窗口构造是否一致。

10 · PyTorch：最小自注意力实现

示例假设批量大小 32、序列长度 20、每个 Token 的特征维度 128，使用 4 个注意力头。

import torch
import torch.nn as nn

batch, seq_len, d_model = 32, 20, 128
x = torch.randn(batch, seq_len, d_model)

attn = nn.MultiheadAttention(
    embed_dim=d_model,
    num_heads=4,
    batch_first=True,
)

# Self-Attention：Q、K、V 都来自 x
y, weights = attn(x, x, x, need_weights=True)

print(y.shape)       # [32, 20, 128]
print(weights.shape) # 常见默认平均各头：[32, 20, 20]

如何读懂形状？

张量形状含义
x[B, T, D]B 个样本，每个 T 个 Token，每个 Token D 维
y[B, T, D]每个 Token 聚合上下文后的表示
weights[B, T, T]每个 Query 对各 Key 的权重（默认通常对头取平均）

如果需要逐头权重，可以尝试 average_attn_weights=False，通常会得到 [B, heads, T, T]。API 细节可能随 PyTorch 版本变化，请以当前版本文档为准。

调试建议：每次先打印输入、输出、权重的形状；确认没有把 batch 维与 sequence 维搞反；再检查数值是否有限（没有 NaN 或 Inf）。

11 · Padding Mask 示例

# key_padding_mask: [batch, seq_len]
# 对 nn.MultiheadAttention 而言，True 表示忽略该 Key 位置
key_padding_mask = torch.zeros(
    batch, seq_len, dtype=torch.bool
)
key_padding_mask[0, 16:] = True  # 第 0 条序列后 4 帧是 padding

y, weights = attn(
    x, x, x,
    key_padding_mask=key_padding_mask,
    need_weights=True,
)

# 注意：这通常屏蔽作为 Key/Value 的 padding 位置。
# 如果无效 Query 位置的输出也不能使用，需要按任务额外处理。

Mask 是最容易出现 API 语义误解的地方。不同参数（例如 key_padding_mask 与 attn_mask）的布尔值含义和形状要求要分别核对。

12 · 计算复杂度与实时部署

标准全注意力会形成 T×T 的分数矩阵。注意力部分的计算与内存通常随序列长度呈平方级增长，粗略计算量常写作 O(T²D)；逐 Token 的 FFN 通常近似随 T 线性增长（忽略具体隐藏层维度常数）。

  • 短历史窗口下，标准注意力可能是简单有效的选择。
  • 历史窗口很长时，应关注分数矩阵的内存和延迟。
  • 可比较缩短窗口、减少模型维度或减少使用注意力的层数。
  • 评估时使用与部署一致的设备、批量、精度和推理路径。
  • 除了平均延迟，也要测量延迟分布、最坏情况和控制周期是否被满足。
机器人控制系统中，离线回报更高不一定意味着更适合部署。如果推理延迟、抖动或内存占用超过预算，模型可能无法按目标控制频率稳定运行。

13 · 机器人策略与 G1 AME：可探索的设计方向

在决定是否使用注意力前，先弄清楚输入数据的结构和当前模型真正缺少什么能力。以下是可以形成实验假设的方向，并非对某个具体 G1 AME 代码库实现的断言。

A. 历史帧 Token

每帧观测经共享编码器映射为 D 维 Token，再通过时序注意力整合历史，输出供 Actor 使用。

B. 身体部位 Token

将躯干、左右腿、左右臂等特征分组编码，探索跨部位的信息交互。需要明确特征和关节索引。

C. 状态与指令融合

研究状态 Token 与目标速度、参考轨迹、地形特征之间的交互，必要时尝试 Cross-Attention。

D. Actor 前的时序编码器

让注意力编码历史，再把表示传给策略网络；训练和部署必须使用一致的历史缓存机制。

设计前必须确认

  • 观测向量每一维代表什么，是否已经包含历史信息。
  • 控制频率、观测延迟、历史帧数与部署推理预算。
  • 策略是 feed-forward、循环网络，还是已有时序编码器。
  • 训练和部署的观测归一化、缓存和序列边界是否一致。
建议从一个最小改动开始：在可比的基线上增加一个小型历史注意力编码器，保持训练预算和评估条件尽可能一致，再决定是否继续扩大结构。

14 · 怎样验证注意力是否真的有帮助？

强化学习结果会受随机种子、采样、环境随机化和训练波动影响。不要只比较一次运行的最好回报。

15 · 常见错误与排查清单

  • 把权重当作解释：注意力权重是中间计算结果，不等于因果重要性。可用干预、消融和输入扰动进一步验证。
  • 张量维度混淆：确认 [B,T,D] 或 [T,B,D] 与 API 的配置相匹配。
  • Mask 语义错误：确认布尔值语义、维度和 padding 位置。
  • 忽略位置与时间：如果顺序重要，检查模型是否获得适当的位置信息。
  • 训练/部署不一致：窗口长度、归一化、历史缓存和采样间隔必须一致。
  • 只看单次最好结果：用多随机种子和独立评估来减少偶然性。
  • 忽略延迟预算：在真实目标硬件和目标推理路径上测量。

16 · 学习自测

先自己回答，再点击查看参考答案。

问题 1：QKᵀ 的形状通常为什么是 T×T？

因为有 T 个 Query，每个 Query 都与 T 个 Key 计算匹配分数，所以每个样本得到 T 行、T 列的分数矩阵。

问题 2：Softmax 后每一行代表什么？

对某一个 Query 而言，它对各个来源 Key/Value 位置的归一化权重。正常情况下非负且行和为 1。

问题 3：为什么要除以 √dₖ？

点积尺度通常随特征维度增加而变大，缩放有助于避免 Softmax 过度饱和，改善梯度与优化条件。

问题 4：Self-Attention 与 Cross-Attention 的主要区别是什么？

Self-Attention 的 Q/K/V 来自同一组输入；Cross-Attention 的 Q 来自一组输入，K/V 来自另一组输入。

问题 5：机器人历史窗口什么时候需要 Causal Mask？

取决于任务是否要求每个时间位置只能访问当时可见的信息。如果整个历史窗口在当前决策时都已知，双向编码该窗口通常不必仅因它是时序数据就加 Causal Mask；但不能让输入泄露未来状态。

问题 6：如何证明性能提升来自注意力而非模型变大？

建立参数量和训练预算尽量可比的基线，固定评估协议，使用多个随机种子，并做移除注意力等消融实验，同时比较性能和部署成本。
