1. 一个 Transformer Encoder Block

X → Multi-Head Self-Attention → 残差 / 归一化
→ Feed-Forward Network → 残差 / 归一化 → Y

注意力在不同 Token 之间混合信息；前馈网络通常逐 Token 变换特征。残差、归一化和 Dropout 的具体顺序随 Pre-LN、Post-LN 等架构而变化，应该以实际实现为准。

2. 张量形状如何变化

输入 X: [B, L, D]
Q: [B, h, L, dₖ]
K: [B, h, L, dₖ]
V: [B, h, L, dᵥ]
注意力分数: [B, h, L, L]
合并多头: [B, L, h · dᵥ]
输出投影: [B, L, Dₒᵤₜ]

B 是批次大小，L 是 Token 数量，D 是输入特征维度，h 是头数。很多实现使用 h·dₖ=D，但这属于常见设计而不是所有实现必须遵守的条件。若输出投影恢复输入维度，则 Dₒᵤₜ=D。

调试时逐步打印每次 reshape、transpose、flatten 的 shape，并核实维度代表什么。形状相同不代表语义正确。

3. 为什么需要位置或时间信息？

标准自注意力按内容计算 Token 之间的交互，本身不直接标记 Token 来自哪个时刻或空间位置。若顺序或位置对任务有意义，模型需要通过位置编码、相对位置偏置、时间戳或其他结构获得这些信息。

  • 时序任务：历史帧顺序、采样间隔和当前帧定义。
  • 空间任务：网格坐标、相机坐标系、地形位置或关节索引。
  • 变长序列：padding mask 与有效长度；注意不同 API 的 mask 语义。

4. 机器人策略中的序列建模

可以把每帧本体状态编码为 Token，也可以把身体部位或地形单元编码为 Token。不同设计需要不同的位置语义和数据预处理；并不是所有输入都适合直接 token 化。

  • 确认观测是否已经包含历史信息，避免重复编码。
  • 确认训练与部署的窗口长度、缓存、归一化和时间对齐一致。
  • 对比现有 MLP / 时序基线，并尽量控制训练预算与参数规模。
  • 在部署设备上测量平均与高分位延迟，不只看离线回报。
